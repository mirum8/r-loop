## Decisions
- **Driver runs as a terminal CLI outside any Claude session** — proposed as recommended; accepted. Alternatives on the table: a skill that detaches a driver (cost: an idle orchestrating session and a crash nobody reports), or hardening the in-session prose loop (cost: context still grows per phase). Force: determinism — a loop owned by code, not by a model following text — and the 600s Bash cap. *(round 1)*
- **One fresh session per step, not per phase** — proposed as recommended; accepted. Alternative: per-phase units as `fanout.sh` runs today. Force: fresh context per step and a session-level model per step; cost accepted: every handoff goes through disk. *(round 1)*
- **Beside `/r:plan-run --herdr`, not replacing it** — proposed replacing; **corrected** — the user wants existing skills untouched and the driver as an alternative approach. Alternative not taken: replace `--herdr` and make `fanout.sh` the driver's spawn/wait layer. Cost named and accepted: two loop encodings (the pack's `task-review` history shows the lockstep tax). *(round 1)*

- **Per-phase planning in its own session; the implement Workflow is cut into plan-half and code-half** — proposed as recommended; accepted. Alternative: `/r:spec-design` once up front, implement sessions keep in-workflow planning. Force: fresh context between a phase's plan and its code; cost accepted: cutting `task-run-implement.workflow.js` in two with the plan file as the only bridge. *(round 2)*
- **A stalled step is left standing, never killed and retried** — proposed as recommended; accepted. Alternative: ralphex's kill-and-rerun N times. Force: a stall is usually a question waiting for a human, and the open session is the only evidence; cost accepted: an unattended run stops until a person appears. *(round 2)*
- **A failed step halts the run; no automatic retry** — proposed as recommended; accepted. Alternative: one fresh-session retry then halt. Force: matches `plan-run`'s halt semantics — nothing builds on a failed phase; cost accepted: a flaky failure needs a person. *(round 2)*
- **The paused herdr session is the input surface** — proposed as recommended; accepted. Alternative: the driver prompts in its own terminal, ralphex-style. Force: avoids a relay between session and driver (the alarm-channel problem `plan-run` carries). *(round 2)*

- **todo / phase plan vocabulary** — proposed; accepted. Alternative: keep "plan" for both and qualify by path. Force: the CLI's flags and every log line need one unambiguous noun. *(round 3)*
- **The driver lands in code, no session** — proposed; accepted. Alternative: a fourth herdr session running plan-run's finish prose. Force: the irreversible step is the one a model must not perform; cost accepted: a merge conflict halts for a person, ticking needs a script. *(round 4)*
- **Per-step session models in `steps.loop`** — proposed; accepted. Alternative: ralphex-style CLI flags only. Force: one tunable surface, fail-loud substitution notes, recorded in the store beside the other tiers. *(round 4)*
- **Planning session: driver-owned prompt, no workflow edit** — proposed a backward-compatible `stopAfter: "plan"` arg; **overruled** — the user chose a driver-owned planning prompt. Alternative not taken: the one-arg edit with the coding session adopting the plan through the existing resume path. Objection (second encoding of explore → design → plan → Codex review) made once in round 5; see the outcome line below. *(round 4)*

- **Serial in v1; a phase is the unit so waves drop in later** — proposed as recommended; accepted. Alternatives: build waves in v1 by calling the two existing scripts (cost: `--no-merge` worktrees + an ordered land pass, all of which already works in `plan-run`), or never (cost: two tools to know). *(round 5)*
- **No verifier agent in the driver** — proposed; never answered — stated as a boundary after the serial answer. Alternative on the table: `issues-fix`'s per-item verifier fan-out deriving `touches`/`risk`. Force: a `todo.md` already carries `Files:`, `Risk:` and `Done when:`, so the concurrency verdict is `check_todo.py --slice` + `footprint-warn.py` — code, not a model. *(round 5)* **REVERSED in round 19 (decision review): the user chose "an agent verifies each phase"** over the recommended no-verifier default; the alternative on the table was the one logged here (a per-phase agent deriving risk and touched files). ADR-12 is superseded. Round 19b settled the shape: **the watchdog is the verifier, at each phase start** (the user picked it over the recommended separate pre-plan step kind and over one pass at run start; costs named: the watchdog gains a second job and its pane must be up before any phase), and **its result may only warn on a mismatch** (chosen with the recommendation; alternatives: halt the phase, or rewrite the plan's fields). It derives the phase's risk and touched files, compares them with the plan's `Risk:` and `Files:`, and emits a warn Signal on disagreement — a veto-tier action under ADR-32, so driving characteristic #1 holds. *(round 5 · corrected in round 19)*
- **Resume exactly at the stopped step, except an unclaimed tree** — recommended in round 5 prose; no objection. Alternative: restart the phase from planning. Force: `fanout.sh`'s state dir and `plan-ledger.py` already do most of it; the unclaimed-tree case stops because guessing either way is wrong. *(round 5 · chosen — reviewed in triage, kept, round 19)*
- **Stall detected from herdr agent state, timer as backstop** — recommended; no objection. Alternative: ralphex's timer-only. Force: asymmetry — a false stall costs one glance, timer-only costs hours on a 3am question. *(round 5 · chosen — reviewed in triage, kept, round 19)*
- **The land gate re-runs the phase's `Done when:`** — recommended; no objection. Alternative: trust the review's `build: green`. Force: 33 recorded reviews returned `build: "n/a"`, 31 of them over Go worktrees carrying 42k added lines reviewed without a compile; the merge is the irreversible step. A phase with no `Done when:` is a named skip. *(round 5 · chosen — reviewed in triage, kept, round 19)*
- **Per-step backstop timers — plan 1h, implement 4h, review 2h** — recommended; no objection. Alternative: one flat 4h. Force: planning never legitimately takes 4h, so a flat number finds a hung planner three hours late. *(round 5 · chosen — decided in review, round 19)*

Alternative: `$TMPDIR`, whose cost is that a reboot mid-run loses the resume point and the phase restarts from planning. Force: resume is a driving characteristic and a driver run can span days, where a fan-out unit lives minutes. *(round 9)*
- **`notify.onHalt` / `notify.onDone` shell hooks** — proposed; accepted. Alternatives: nothing at all, or hook points named in the spec but unimplemented in v1. Force: a run that halts at 3am is otherwise found in the morning. Constraint recorded: a failing hook must never fail the run. *(round 9)*
- **`todo.md` is the only source in v1** — offered for veto; kept. Alternative: `--task "..."` for a single phase-shaped unit, whose cost is no `Done when:` to gate the land on, making that gate conditional. *(round 9)*
- **`--provider <step>=<name>` per-run override** — proposed; accepted. Alternative: config only. Force: trying a provider should not mean editing the project config and putting it back. Constraint: the run banner prints the resolved row, since a flag can contradict the file. *(round 9)*

- **The driver is a Go TUI; `--plain` stays for scripts and CI** — proposed; accepted. Alternative: TUI only, whose cost is that the driver cannot run from a script, a cron, or a pane with no TTY. This also closes the round-9 open question (bash vs Go) in Go's favour and voids the bash-3.2 technology row and its StateStore risk. *(round 10)*
- **Agents ask through an MCP server the driver exposes (`ask_user`)** — proposed; accepted. Alternatives: a small CLI the agent shells to (works on any agent with a shell, but is a convention rather than a discoverable tool), or both. Force: MCP is to the tool channel what herdr `--kind` is to the session channel — one contract every candidate provider already speaks. *(round 10)*
- **An open question is its own `waiting-input` state, exempt from the step's backstop** — proposed; accepted. Alternative: a question still counts against the timer, whose cost is a step killed for asking at 3am. *(round 10)*
- **The review step runs the provider's native reviewer** — proposed; accepted. Alternatives: always open a session and have the agent invoke its own reviewer inside it (one shape, but pays for a session where `codex review` runs headless), or keep the driver's own review prompt with the native one as an extra pass (gives up most of the gain). Force: the pack's "a real tool, never a prose imitation" rule, and it buys back part of what ADR-4 spent. *(round 10)*
- **The review step is always two halves — find, then fix in a session** — proposed; accepted. Alternatives: one half where the provider can do both (`/code-review --fix`), whose cost is two step shapes and a fix behaviour that differs by provider; or a separately configurable fix step, whose cost is a fourth row and a fixer that never read the review's reasoning. *(round 11)*

Alternatives: `report_progress` (rejected — progress an agent reports is a claim, which this design refuses to act on) and `report_finding` (rejected for v1 — every provider would have to emit one shape). *(round 11)*
- **`ask: none` is a named degradation** — decided, not asked: a provider that cannot host an MCP server runs its steps with no ask channel and the run report says so, exactly as `fanout: none` does. *(round 11 · chosen — reviewed in triage, kept, round 19)*
- **A subprocess review is a Step with no Session** — decided, not asked: the two-signal rule still applies; nothing is watchable in herdr while it runs. **CORRECTED in round 19**: the user answered "codex has /review command" — the reviewer can run inside a session, so the review step has one shape, a session, with the native reviewer invoked inside it; the headless subprocess shape goes. This flips ADR-23's rejected alternative into the decision and is written as a new ADR superseding that clause. *(round 11 · corrected in round 19)*
- **The fix half runs on the `implement` provider row** — decided, not asked: it patches code the implement step wrote, and the pack's one-writer rule says the model that wrote a change is the model that patches it. `steps.loop.review` therefore governs only the find half. *(round 11 · chosen — reviewed in triage, kept, round 19)*
- **The driver runs in a herdr pane; it is one process, not a daemon plus a client** — proposed; accepted. Alternative: a headless driver with an attachable TUI, whose cost is an IPC boundary and a daemon lifecycle — roughly ralphex's `--serve` in scope. Consequence to document: a run started in a plain terminal dies with it. *(round 12)*
- **Bubble Tea + Lip Gloss** — proposed; accepted. Alternative: tview/tcell, less ceremony for tables but less idiomatic for a streaming event log. *(round 12)*

- **A watchdog agent runs in a pane beside the TUI, and it may only VETO** — the core decision of round 14. It can halt, warn and ask; it can never mark a step done, approve a landing, unblock or resume. Force: approvals and vetoes are asymmetric — a model wrong on an approval lets bad work land, a model wrong on a veto costs a resume. This is what keeps Part 3's first driving characteristic true, and that characteristic is reworded from "zero loop decisions made by a model" to "zero loop APPROVALS". *(round 14)*
- **Mechanical anomalies are driver checks; the watchdog covers judgement** — decided from the design's own rule. Deterministic: files outside `Files:`, a step running far longer than the same step on earlier phases, diff size far beyond earlier phases, the plan or a checkbox touched mid-step, a test file modified the step did not create. Judgement: the change is solving a different problem than the phase asked for, the session is going in circles, implement has started redesigning, review's fixes are undoing implement's work, the phase's premise looks wrong now the code exists. Without the split the watchdog is a model re-implementing `git status`. *(round 14 · chosen — decided in review, round 19)*
- **The watchdog reads live session output as well as disk and git** — proposed; accepted. Alternative: disk and git only, which is cheaper and reads only evidence, but sees a wrong turn only once files change. Force: a wrong path is visible in the session's output long before the diff, and `herdr agent read` is the only access to it. Constraint recorded: session output is a claim, so a halt must be confirmed against git first. This ALSO defeats the round-13 recommendation of spawn-per-question — a trajectory is not reconstructible from disk, so the pane is load-bearing. *(round 14)*
- **A watchdog halt takes effect immediately** — proposed; accepted. Alternative: it proposes and the TUI confirms, whose cost is that at 3am nobody confirms and the wrong path runs to completion — the case it exists for. Consequence: the run report records every halt the watchdog called, so its threshold can be tuned from rows. *(round 14)*
- **A watchdog halt stops the current step, not just the schedule** — proposed; accepted. Alternative: stop scheduling and let the live step finish, whose cost is a wrong implementation writing for another half hour. Consequence: the driver needs a way to stop a running session, which is a new herdr interaction. *(round 14)*
- **Two severities: warn (banner + `notify.onWarn`, run continues) and halt** — decided: if every signal is a halt it is unusable, if none is it is decoration. *(round 14 · chosen — reviewed in triage, kept, round 19)*

- **The watchdog gets three tiers of authority, not one** — round 15 widens round 14's veto-only rule. VETO (halt, warn) is unilateral; REMEDY (fix the environment, restart a step, retry with an addendum, retry on another provider) needs consent; APPROVE (step done, phase may merge, tick, land) is never permitted, not even with consent — a human clicking yes on a watchdog's summary is worse evidence than the driver's own check of git. Consent can authorise an action; it cannot substitute for evidence. *(round 15)*
- **Consent is an allow-list in config, empty by default** — proposed; accepted. `watchdog.allow` pre-authorises classes of remedy; anything else asks. Alternatives: always ask (an unattended run still stops for a person — the cost the feature exists to remove) and ask-once-per-class-per-run (consent granted in one context silently reused in another). *(round 15)*
- **All four remedies ship in v1** — environment fixes, restart the step in a fresh session, retry with an addendum to the prompt, retry on a different provider. The restart is what makes a fix worth anything; without it a repaired environment leaves the run halted anyway. *(round 15)*
- **A question reaches the watchdog first, escalating to the human when it cannot cite an answer** — proposed; accepted. Alternative: the human first with the watchdog advising, whose cost is that the run stops for a person on every question. Every answer is logged and shown in the TUI. *(round 15)*
- **The watchdog proposes the exact command; the driver authorises; the watchdog runs it; the driver records it verbatim** — decided, not asked. Alternative on the table: the driver executes every remedy itself, which types and records each one but limits remedies to those pre-implemented — too narrow for open-ended environment repair. The allow-list stays authoritative in the driver so the watchdog can never approve its own action. Offered in review with a third option, the driver running the proposed command itself; the user kept the watchdog as executor. *(round 15 · chosen — decided in review, round 19)*
- **The watchdog still must never** edit code or tests (an unreviewed writer), edit the plan (ADR-16's unclaimed-tree stop exists because a second writer to the tree is unaccountable), merge, push, delete anything holding work, or answer its own consent prompt. *(round 15)*
